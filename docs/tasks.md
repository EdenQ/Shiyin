這些會跳出系統的權限詢問或選單，使用者不在時不能做。使用者到 2026-10-21 錄的都只有麥克風（`channels='mic'`），麥克風、即時逐字稿、錄音中的畫面已經實際用過。

- [~] **電腦聲音**（§5.1、R1；原 T-A2、T-B4）：播 YouTube 或 Meet 錄 5 分鐘（麥克風＋電腦聲音），沒有斷音、兩邊時間差在 100 ms 以內；權限被拒時的說明
- [~] **錄音中換裝置**（§20.2、R18.2；原 L10）：錄音中接上、拔掉耳機，麥克風重新接上、錄音不中斷；換輸出裝置，電腦聲音用新的裝置繼續錄。看門狗、重新連接、雙聲道補靜音已經用模擬錄音驗證過
- [~] **偵測會議**（§21.7，R19.4，D31）：提醒、開始、停止、不要再提醒、恢復提醒、30 秒收起、設定用模擬的 app 驗證過；要真的用 Zoom 或 Meet 開會
- [~] **通知**（R11.2；原 T-F4）：這台電腦對拾音的通知權限是「拒絕」，打開後確認實際收到通知、點通知會選到那場會議、偵測會議的通知按鈕
- [~] **全域快捷鍵**（R11.3、R19.5；原 T-F8）：在別的 app 按 ⌃⌥⌘R，沒在錄就開始、在錄就停止；錄音中按 ⌃⌥⌘B 標記重點
- [~] **分享**（R7.5；原 T-D6）：匯出對話框按「分享…」選 Mail，附件有帶過去
- [~] **API 整理工具用真的 key**（R6.1、R17；原 T-C2、T-K3）：Anthropic API 整理和校稿；OpenAI API（目前的帳戶沒有額度，只測到錯誤訊息）；Groq 等 OpenAI 相容服務（只用 Codex 回答的本機伺服器測過）
- [~] **讀 API key 的確認視窗**（§22.1，R21.1～R21.4，D36）：用 `keychainsim` 模擬驗證過；真的鑰匙圈跳出確認時按「拒絕」，整理失敗的訊息要是「macOS 沒有讓拾音讀取…」；按「允許」（不是永遠允許）後，同一次開著拾音整理、校正、猜說話者只問一次
